# Передача работы: восстановление mzCorp

Состояние на 05.11.2026, сверено с сервером. Этот файл — точка входа для новой сессии на любом компьютере. Подробности: `RETRO_PLAN.md` (план по этапам), `RETRO_NOTES.md` (находки, правила сборки, грабли), `PLAN.md` (сервер и остальное восстановление).

Репозиторий **публичный**. IP сервера, адреса сотрудников и клиентов, значения ключей и `CATALOG_SYNC_URL` в него не класть.

## Как продолжить с другого компьютера

```bash
git clone https://github.com/markyel/mzcorp.git
```

```bash
cd mzcorp && git checkout recovery/retro-import
```

```bash
composer install
```

```bash
php vendor/bin/phpunit tests/Unit/Retro --no-coverage
```

Должно пройти 27 тестов. Проверка не трогает базу.

- **Сервер:** Reg.ru, выделенный RD-59257. IP смотреть в панели Reg.ru. Вход `ssh root@<IP>` по паролю. На новом компьютере ключа нет, вход по паролю оставлен намеренно: **не отключать**.
- **Заметки ассистента:** на новом компьютере их нет. Скопировать по инструкции `claude-memory/README.md`. В копии адреса и IP вырезаны.
- **Первое сообщение новой сессии:** «Прочитай deploy/recovery/HANDOFF.md, проверь состояние сервера и продолжим».

## Обязательные правила

- GPT на старых письмах не используем.
- При загрузке ни одного письма наружу и ни одного изменения в ящиках: читаем только через `RetroImapReader` (`EXAMINE`, `BODY.PEEK`).
- Номер 1С только из имени файла КП. Номера счетов в это поле не подставлять.
- artisan, tinker и git на сервере только от `www-data`. Иначе лог создаётся под root и воркеры встают.
- Не включать воркеры и cron, пока не пройден этап 6 плана: они начнут закрывать старые заявки и рассылать тревоги.
- Пользователю писать по-русски, коммиты на английском, коммитить и пушить только по просьбе.

## Что сейчас на сервере

- Код лежит в `/var/www/mzcorp`: git стоит на `main@21fc1785`, поверх архивом выложены файлы ветки. Прикладной код совпадает с `90ae89c1` по контрольным суммам. На сервере нет `deploy/recovery/retro-rebuild.sh`, `deploy/recovery/tools` и тестов `tests/Unit/Retro`.
- Выкладка правок, пока сервер не переведён на git (из Git Bash, в корне проекта):

  ```bash
  tar cf - <файлы> | ssh root@<IP> 'sudo -u www-data tar xf - -C /var/www/mzcorp'
  ```

  Затем от `www-data`: `php artisan view:clear` и `php artisan config:cache`.
- Воркеров, cron и фоновых процессов нет. `MAIL_MAILER=log`. Ключа OpenAI нет. В очереди 1 задача (`ResolvePendingFromCatalogJob`).
- Только на сервере, в `.env`: `CATALOG_SYNC_URL`, `RETRO_MZ_FOLDER_OWNERS`, ключи Яндекса. В базе: токены ящиков. В `/root`: `db-passwords`, `mzcorp-admin-password`.
- Индекс писем: `storage/app/retro`, 94 МБ. Из него сборка повторяется без чтения почты. Кеш текстов: `/var/lib/postgresql/retro-bodies.copy`. Журналы: `storage/logs/retro/`, `/var/tmp/retro-*`.
- **Резервных копий нет.** Индекс, база и файлы существуют только на этом сервере.

## Ловушки перед следующими шагами

- **Кнопки отправки на сайте работают по-настоящему.** `MAIL_MAILER=log` не защищает отправку из карточки, которая идёт через ящик. Тестовое письмо 04.11 реально ушло.
- **Пересборка стирает всё, что сделано в `MyLift_retro` через сайт.** `retro-rebuild.sh` удаляет базу и копирует её из `MyLift`. Ящики и пользователи сейчас в обеих базах совпадают. Подключение Милючихина, смена ролей и паролей, правки РОПа нужно делать в обеих базах или повторять после сборки.
- **Пересборка меняет id писем.** Скачанные файлы лежат в `storage/app/private/mail/<ящик>/<id письма>/` и к новой сборке не привязаны. Скрипт скачивает их заново и заново считает суммы. Старые папки остаются на диске и могут совпасть по id с новыми: перед финальной сборкой решить, чистить ли их.
- **Перед пересборкой** отключить сайт от целевой базы или собирать в другую: при открытых сессиях `DROP DATABASE` не пройдёт. Каталог после сборки импортировать заново: `catalog:sync-from-url --force`.
- **Просмотр меняет статус.** Открытие карточки ответственным переводит `new` и `assigned` в `in_progress`.
- **Приватный репозиторий.** Перевод в приватный рекомендован, но `git pull` на сервере идёт по https: сначала нужен deploy-ключ.
- **Ежов.** Его ящик отмечен активным: при включении синхронизации система начнёт разбирать его почту. Отметка недоступности истекает 04.03.2027, учётку отправить в архив.

2. **Цепочки без номера** с активностью за 30 дней: заявки с номерами от 30001. Не написано.
