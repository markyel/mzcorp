IQOT = внешний сервис анализа цен конкурентов (Public API v1, `iqot.ru/api/v1`). Интеграция портирована из LazyLift (`C:\Work\LazyLift`, файлы `app/Services/IqotApiService.php`, `app/Models/IqotSubmission.php`, `PollIqotSubmissionsJob` и т.д.) и адаптирована под MyLift. Реализовано 2026-06-05.

## Суть
Единица анализа — **позиция каталога (`catalog_item`)**. Пул наполняется: (1) auto — catalog-matched позиции заявок, которые БЫЛИ «КП отправлено» (любым путём!) и закрыты в потерю; (2) manual — кнопка «IQOT — анализ» в карточке каталога (РОП/директор).
**Источник auto — ТОЛЬКО реально проквотированные позиции (переписано 2026-06-23, commit 3fe552e):** КП уходит ДВУМЯ путями — структурный `Quotation`(sent) И вложением через детектор (`outbound_quotes`/`outbound_quote_items`). Единица анализа — «лот, на который МЫ ДАЛИ цену и проиграли». `refreshPoolFromLostQuotes` берёт catalog_item, у которого ЕСТЬ строка в КП проигранной (`closed_lost`) заявки: `quotation_items`(sent) ИЛИ `outbound_quote_items.matched_catalog_item_id` с `unit_price>0`. `lost_quote_count`=число distinct таких заявок. + **чистка** (commit a4fa806): auto-позиции вне quoted-set удаляются ТОЛЬКО если нетронуты — `analyzed_at IS NULL AND last_enqueued_at IS NULL` (баланс НЕ потрачен); позиции с оплаченным отчётом/отправленные НЕ трогаем (офферы оплачены и ценны, даже если не квотировали); manual/excluded_at тоже не трогаем; гард непустого set. **ГРАБЛЯ:** первая версия чистки (3fe552e) снесла 502, из них 119 уже отправлялись в IQOT (баланс потрачен) — восстановлены командой `iqot:recover-deleted-positions --apply` (воссоздаёт позицию из `iqot_submissions`: `catalog_item_ids`+`report`/`payload`, маппинг по индексу; офферы не теряются — лежат в submission). Кейс M26928 (башмак): не квотировали, но оффер 999 ₽ оплачен → восстановлена `completed` с our_unit_price=null/our_rank=null (оплаченные данные есть, ложного сравнения нет, «В КП»=«—»). **ГРАБЛЯ (была до 3fe552e):** старый алгоритм брал ВСЕ `request_items` заявок с переходом в `quoted` → в пул лезли позиции, которые в КП НЕ попали (кейс M26928: башмак в 3 заявках, но ни в одном из 3 КП → нет нашей цены → сравнение с каталожным 0). Прод: 502/1626 auto не были квотированы (63 потратили баланс зря) → убраны; стало 1795 auto, у ВСЕХ есть our_unit_price, 0 ложных рангов. qty/unit = `RequestItem::effectiveQty()/effectiveUnit()` последней проквотированной заявки. Крон раз в 2 часа в рамках **дневного лимита** отбирает приоритетные (manual → lost_quote_count desc → старшие) и шлёт одной submission; poll-крон ежечасно тянет отчёт и раскладывает по позициям. Позиция со **свежим** отчётом (окно `iqot.report_fresh_days`, дефолт 90) повторно не анализируется и подсвечивается в редакторе КП и карточке каталога.

**КЛЮЧЕВОЕ правило: M-артикул (`catalog_items.sku`) НЕ отправляется в IQOT И не показывается как OEM.** Шлём/показываем `name` каталога + настоящий OEM. Правило централизовано на модели: `CatalogItem::oemForExternal()` / `brandForExternal()` (+ `static isInternalCode($value,$sku)`) — отсекают значения, равные sku или похожие на M-код (`/^M\d{3,}$/i`, `МЗ-…`), т.к. `brand_article` иногда дублирует sku (напр. M19678). Используется И в `IqotPoolService::buildLine` (payload), И в blade раздела (колонка OEM — без fallback на brand_article). Коммит дисплея: 32d6a37.

## Количество/единица для запроса
qty+unit в `iqot_positions` берутся из ПОСЛЕДНЕГО проигранного КП по позиции (`refreshPoolFromLostQuotes`, DISTINCT ON по `q.sent_at DESC`). buildLine шлёт их (а не «1 шт»): напр. канат M26310 → 576 м. **Каталожный `unit_name` как единицу НЕ используем** — это поле «Узел» (напр. «Шахта лифта…»), не мера; fallback только «шт.». Ручные позиции (без КП) → qty=null → 1 шт. Коммит 4c6b6ee.

## Исключение позиций («не запрашивать никогда»)
`iqot_positions.excluded_at` (+ `excluded_by_user_id`) и статус `IqotPositionStatus::Excluded`. Исключённые: пропускаются `refreshPoolFromLostQuotes` (не возвращаются в pending), `IqotDispatchService` (whereNull excluded_at), и `PollIqotSubmissionsJob::applyReportToPositions` (поздний отчёт не перетирает). В разделе — кнопки «Исключить»/«Вернуть в пул» + фильтр «Исключённые» (по умолчанию скрыты из активного списка). Явный ручной запрос из каталога (`enqueueCatalogItem`) снимает исключение. Коммит fff882d.

## Как включить (прод)
По умолчанию **выключено** (`iqot.enabled=false`, ключ пуст → крон no-op, баланс не тратится). Включение: Настройки → «IQOT · анализ цен» → задать **API-ключ** + включить **iqot.enabled** (+ при желании daily_limit/fresh_days). Дальше крон сам, либо кнопка «Запустить анализ» в разделе.

## Прогресс сбора (до отчёта)
Ответ `GET /submissions/{id}` несёт `items[]` с `status` (dispatched/awaiting_suppliers/with_offers/…), `offers_count`, `report_available`, `classification`, `counts{total,accepted,rejected,dispatched,…}`. `PollIqotSubmissionsJob::applyStatusToPositions` пишет live `report_offers_count` + `iqot_positions.iqot_item_status` (для незавершённых), раздел показывает под «Анализируется» стадию. Коммит 5f404af.

## ГРАБЛЯ client_ref (важно)
IQOT **возвращает `client_ref` в items только на ранней стадии**, а после dispatch его УБИРАЕТ. Поэтому сопоставление позиций — `resolvePositionId()`: сначала по `client_ref` (`pos-{id}`), иначе **по индексу** (items[] ответа идут в порядке нашего `payload.items[]`, где client_ref есть). Применяется и к статус-прогрессу, и к раскладке отчёта. Коммит e95f7a4. Проверено: status=ready→dispatching, counts accepted 3/3, классификация по позициям корректная (Редукторы/Канаты/Платы).

## Схема отчёта IQOT (ПОДТВЕРЖДЕНО реальными данными, коммит 0c639a3)
Item отчёта (и в last_status_response.items[], и в report): `all_offers[]` (каждый: `price_per_unit`, `total_price`, `supplier{id,name,email,phone}`, `delivery_days`, `vat_label`, `notes`, `received_at`, `currency`), `best_offer_by_price` (тот же объект), `offers_count`, `minimum_threshold`(=3), `status` (collecting/…), `classification.product_type.name`. Офферы приходят ИНКРЕМЕНТАЛЬНО (видны даже при 1<threshold). `extractMinPrice` = best_offer_by_price.price_per_unit → min(all_offers price_per_unit/total_price). `IqotPosition::offers()`/`minPriceFromReport()` — для UI/бэкфилла. Раздел: разворачиваемый список офферов (поставщик/цена/срок/НДС/контакты/примечание); карточка каталога при свежем отчёте даёт ссылку «Все предложения →» (route iqot.index?q=sku), БЕЗ повторной отправки.

## Сравнение «наша цена vs офферы» с НДС (коммиты 1a6c49e…207d902/fe9afcb, как в LazyLift)
`IqotPosition::priceComparison()` объединяет офферы + нашу строку, **ранжирует по цене БЕЗ НДС**, считает наш ранг + дельту vs лучший IQOT. Вывод (разворот строки раздела): исходная цена + пометка «с НДС/без НДС» И колонка «Без НДС» (база сравнения); наша строка подсвечена.
- **База нашей цены — ГИБРИД (коммит 207d902):** был структурный КП → `our_unit_price` (метка «Наше КП <code>»); иначе (детектор/ручной) → `CatalogItem.price` (метка «Наша цена (каталог)» + price_min-нота, «цена не актуальна» при is_price_actual=false).
- **НДС (коммит fe9afcb, ВАЖНО — ранее ОШИБОЧНО считал net):** и `QuotationItem.final_unit_price`, и `catalog.price` хранятся **С НДС** (`line_total/1.22*0.22 = vat_amount`). Нашу цену тоже делим на `1+tax.vat_percent` для ранжирования, выводим «с НДС». Офферы: `price_includes_vat` → делим, иначе как есть.
- `Iqot\Index::positions()` грузит у catalogItem price/price_min/is_price_actual/lead_time_days. Эталон вёрстки: `C:\Work\LazyLift\resources\views\livewire\admin\request-detail-iqot.blade.php`.

## Конвертация валют офферов в ₽ (коммит c035211, 2026-06-08)
Офферы IQOT приходят в РАЗНЫХ валютах — у каждого оффера поле `currency` (RUB/USD/EUR/CNY). Раньше `price_per_unit` трактовался как рубли → китайский PASSION ELEVATOR с «80 USD» ранжировался как «80 ₽» (дешевле нашего КП 2300 ₽), дельта «+3403%». Плюс сам IQOT в `best_offer_by_price` выбирает минимум по голому числу без валюты — **доверять ему нельзя**. Фикс:
- **`app/Services/Iqot/IqotCurrencyConverter.php`** (static): `normalize` (синонимы/символы→ISO), `symbol`, `toRub($amount,$currency)` → `{rub,rate,currency,converted,known}` (RUB→1.0, неизвестная валюта/незаданный курс → rub=null), `minRawRub($offers)` (min по rub-эквиваленту, fallback на голый min).
- **Курсы** редактируются в Настройках («IQOT · анализ цен»): `iqot.fx_usd/fx_eur/fx_cny`; дефолты в `config('services.iqot.fx_rates')` (USD 90 / EUR 100 / CNY 12.5 — **заглушки, обновлять руками**). Онлайн-котировки НЕ тянем — курс приблизительный, UI помечает.
- **`IqotPosition::priceComparison()`** ранжирует по net в РУБЛЯХ (`net_rub`); строки с неизвестным курсом уходят в конец, исключены из «лучший IQOT»/ранга/дельты. Каждый row несёт `currency/currency_symbol/converted/rate/rate_known/raw_rub/net_rub`.
- **`minPriceFromReport()` + `PollIqotSubmissionsJob::extractMinPrice()`** → «Мин. цена» в ₽ через `minRawRub`, БЕЗ `best_offer_by_price`.
- **`_comparison.blade.php`**: символ валюты вместо хардкода `₽`, под ценой `≈ N ₽ · курс ~` (amber) для инвалюты / «курс <C> не задан» (red) для неизвестной, заголовок «Без НДС, ₽», `*` на сконвертированных + сноска.
- **Бэкфилл** после деплоя: пересчёт `report_min_price` по сохранённым отчётам (`$pos->minPriceFromReport()`); live-сравнение чинится само (считается в рантайме), кешируется только колонка «Мин. цена». На проде проверено POS 184 (M03035): наша цена 1/3, дельта −3132 ₽ (−57,7%), мин.цена 6624,60 ₽.

## Авто-обновление курсов из ЦБ РФ (коммиты d58689c/0145d09, 2026-06-08)
Дефолтные курсы — заглушки и дрейфуют, поэтому тянем официальные дневные курсы USD/EUR/CNY из **ЦБ РФ** (без ключа) в те же настройки `iqot.fx_*`.
- **`app/Services/Iqot/CbrFxRateProvider.php`**: `fetch()`/`parse()` XML `cbr.ru/scripts/XML_daily.asp` (URL в `config services.iqot.fx_source_url`). Курс за 1 единицу = `VunitRate` или `Value/Nominal` (юань исторически Nominal=10; запятая→точка; windows-1251→UTF-8). Возвращает `{rates:[USD,EUR,CNY], date}`. Сеть-фейл → пустой результат (старые курсы сохраняются).
- **`iqot:update-fx-rates`** (`--dry-run`/`--force`): уважает тумблер `iqot.fx_auto_update` (TYPE_BOOL, дефолт true — выключив, оператор «пинит» ручные курсы; `--force` игнорит). Пишет курсы через `SettingsService::set(TYPE_FLOAT)` + штамп `iqot.fx_updated_at` (TYPE_STRING). **После смены курсов рефрешит кешированный `report_min_price`** у всех позиций с отчётом (`refreshCachedMinPrices` → `minPriceFromReport`), т.к. колонка «Мин. цена» хранится в ₽ по текущему курсу и иначе отстаёт на день. Live `priceComparison` рантайм — рефреш не нужен.
- **Крон** `Schedule::command('iqot:update-fx-rates')->dailyAt('07:30')->timezone('Europe/Moscow')` (ЦБ публикует курс на дату накануне вечером). No-op оффлайн.
- **Настройки**: тумблер `iqot.fx_auto_update` в группе «IQOT · анализ цен», help-тексты курсов помечены «обновляется автоматически из ЦБ РФ». `iqot.fx_updated_at` НЕ в schema (системный штамп, в UI не показывается). `iqot.fx_auto_update`/`fx_updated_at` НЕ в configMap — `configDefault` отдаёт schema-default (true) для ключей вне мапы, это ок.
- **Прод 2026-06-08**: первый прогон — USD 90→73.4689, EUR 100→85.5582, CNY 12.5→10.853 (курс ЦБ на 06.06). POS 184: наша цена 1/3, дельта −2520 ₽; «Мин. цена» сместилась на PASSION 5877.51 ₽ (80 USD).

## Статус «Без предложений» (no_offers, коммит d74a124, 2026-06-08)
IQOT отдаёт `completed`, даже когда поставщики прислали 0 офферов — такие позиции засоряли список «Готов отчёт» (сравнивать не с чем). Новый case `IqotPositionStatus::NoOffers='no_offers'` (label «Без предложений»). `PollIqotSubmissionsJob::applyReportToPositions`: при раскладке отчёта если `extractOffersCount==0` → статус `no_offers` вместо `completed`. **Самокорректируется**: отчёт переприменяется на каждом опросе (нет completed-гарда в applyReportToPositions), офферы приходят инкрементально → при появлении первого оффера статус вернётся в `completed`. UI: чип-фильтр «Без предложений» в разделе (amber), кнопка «Повторить» работает и для `no_offers` (если отчёт устарел). `no_offers` имеют analyzed_at → `hasFreshReport`=true → НЕ переотправляются в fresh-окне (dispatch берёт только `pending`; refreshPoolFromLostQuotes скипает fresh) — баланс не тратится. Колонка `status` varchar(24). Бэкфилл прод 2026-06-08: из 44 completed 19 → no_offers (осталось 25 настоящих).

## Критический алерт «выше рынка» (коммит 313bdb1, 2026-06-08)
Второй тир поверх «пересмотреть цену»: «кричащий» алерт когда наша цена в топ-N% самых дорогих ПРИ выборке ≥ min_suppliers поставщиков. `IqotPosition::isCriticalPricing()` по кешу cmp_*: `suppliers = cmp_total-1 ≥ min_suppliers` И `(cmp_our_rank-1)/cmp_total ≥ 1-top_pct/100` (доля более дешёвых ≥ 0.8 = топ-20%). Пороги config/Настройки `iqot.critical.top_pct`(20)/`min_suppliers`(4) (ключи `iqot.critical_top_pct`/`critical_min_suppliers`). `pricingAlert()` (заменил pricingAttention для бейджа) возвращает level critical|attention + rank/total/deviation/suppliers. UI: критическая строка — `bg-red-50 hover:bg-red-100 border-l-2 border-l-red-500` (весь `<tr>`), бейдж красный «🔴 выше рынка · N-е из M · +X%»; обычная — amber «⚠ пересмотреть цену». Критические сортируются НАВЕРХ списка (orderByRaw перед manual-first). Скоупы: `scopeCriticalPricing` (только критич.), `scopeNeedingPricingAttention` расширен = мягкий (rank≥min_rank И dev>порог) ИЛИ критический (SQL `(cmp_total-1)>=? AND (cmp_our_rank-1)::float/cmp_total>=?`). Шапка показывает «🔴 Выше рынка: N» (stats['critical']). Прод 2026-06-08: 6 критических (все rank 5/5 при 4 поставщиках, dev +80..+762%, вкл. M00030 +104% из примера заказчика), attention(вкл крит)=25.

## Фильтр «требуют внимания» + кеш сравнения (коммит 2e0f588, 2026-06-08)
priceComparison() считается в PHP по JSON-отчёту → фильтровать пагинированный список по нему нельзя. Закешировали сигналы в колонки `iqot_positions`: `cmp_our_rank` (smallint), `cmp_deviation_pct` (decimal 10,2), `cmp_total` (smallint) — миграция `2026_06_08_140000_add_comparison_cache_to_iqot_positions`. Заполняются: (1) `PollIqotSubmissionsJob::applyReportToPositions` (set `$pos->report=$entry` ПЕРЕД priceComparison, т.к. оно читает $this->report), (2) `IqotUpdateFxRatesCommand::refreshCachedComparison` (бывш. refreshCachedMinPrices — теперь обновляет и report_min_price, и cmp_*, т.к. отклонение зависит от курса). SQL-скоуп `IqotPosition::scopeNeedingPricingAttention` = `cmp_our_rank>=min_rank AND cmp_deviation_pct>min_dev` — пороги ЖИВЫЕ (`attentionMinRank()`/`attentionMinDeviationPct()` из app_setting), правка в Настройках влияет на фильтр сразу. `pricingAttention()` переписан на чтение cmp_* (а не live priceComparison) → бейдж и фильтр согласованы. UI: чип-тумблер «⚠ Требуют внимания» (`#[Url] attn`, `$toggle`) + счётчик из `stats['attention']`. Прод 2026-06-08 после бэкфилла (`iqot:update-fx-rates --force` пересчитал 49 поз.): cmp_our_rank у 49, cmp_deviation_pct у 28, под флаг попало 9 (M05766 +999%, M04057 +677%/3-е, M21731 +474%/3-е, …). NB: данные «дозревают» — число флагов растёт по мере накопления офферов и каталожных цен.

## Флаг «пересмотреть цену» в готовых отчётах (коммит 3d85d5f, 2026-06-08)
В списке «Готов отчёт» позиция помечается амбер-бейджем «⚠ пересмотреть цену · N-е · +X%», если наша цена занимает место ≥ min_rank ИЛИ ниже **И** отклонение от лучшей цены IQOT (без НДС) > min_deviation_pct %. ОБА условия (AND, по решению заказчика). `IqotPosition::pricingAttention()` использует `priceComparison()` (our_rank/delta_pct в рублях). Пороги: `iqot.attention.min_rank` (3) + `iqot.attention.min_deviation_pct` (10) в config + Настройках (ключи `iqot.attention_min_rank`/`iqot.attention_min_deviation_pct`). Бейдж рисуется только для `status=completed` в `index.blade.php` (ячейка позиции). **Реальность данных 2026-06-08:** из 28 completed только у 2 есть наша цена (остальные 26 — нет catalog.price/КП → our_rank=null, не сравнить); те двое (M26310 +84%, M05766 +999%) на 2-м месте из 2 (1 оффер) → строгое правило ≥3 их НЕ ловит. Флаг «дозреет», когда у позиций накопится ≥3 оффера (minimum_threshold IQOT=3). Заказчик подтвердил: оставляем строгий AND, не ослабляем до ≥2/OR.

## Наша цена: ноль не валиден + источник детектор-КП (коммиты 5d754c7 + b81283e, 2026-06-23)
Две связанные правки нашей цены в `priceComparison`/пуле.
**(1) Ноль ≠ цена (5d754c7):** кейс M26928 каталожный `price=0,00` (`is_price_actual=false`), а `priceComparison` брал `cat->price` по `!== null` → `$ourGross=0` → наша строка «0,00 ₽» = ложное 1-е место, дельта −100%, бейдж «мы дешевле всех». Фикс: `our_unit_price`/`cat->price` требуют **> 0** (как `firstPositivePrice` для офферов), иначе нашу строку не добавляем (`our_rank=null`). Затронуто 4 позиции.
**(2) Источник цены — и детектор-КП (b81283e):** `IqotPoolService::refreshPoolFromLostQuotes` писал `our_unit_price` ТОЛЬКО из структурного `Quotation` (строка ~118), а почти все КП в MyLift уходят **детектором** (вложением, без Quotation) → `our_unit_price=null` → фолбэк на каталог (часто 0). Грабля: `lost_quote_count` («N из КП»/колонка «В КП») = число заявок, дошедших до статуса «КП отправлено» с этой позицией, а НЕ цена позиции (M26928 «3 из КП», но башмак не был ни в одном из 3 КП). Фикс: приоритет **структурный КП → детектор-КП → пусто**. Детектор-цена — `outbound_quote_items.unit_price` по `matched_catalog_item_id`, самая свежая >0 среди ВСЕХ проигранных заявок позиции (`DISTINCT ON`). Чинит M32465 (каталог 0 → реальные 33393 «Наше КП 356185»). M26928 корректно остаётся null (башмак не квотировался).
**Вёрстка `_comparison.blade.php`:** бейдж нашей строки «КП»→**«МЫ»** (источник может быть каталог, не только КП); подпись строки — реальный `$row['notes']` (был хардкод «собственное КП» даже для каталожной цены — это и сбивало с толку).
**Применение на проде:** после деплоя `refreshPoolFromLostQuotes` (updated 1384) + `recomputeComparisonCache(true)` по всем `analyzed_at`. Дисплей раздела чинится сразу (priceComparison live), `cmp_*`-кеш (фильтр/бейдж/сортировка) — после пересчёта.

## Исключение нулевых офферов (коммит c6bf270, 2026-06-09)
Поставщик иногда возвращает оффер с ценой 0 (пустой/ошибочный ответ, напр. Revator 0 ₽ на M06476) — он ранжировался как «1-е место 0 ₽» и сдвигал наш ранг (3/5 вместо 2/4), мог отравить «Мин. цену». Фикс: цена ≤ 0 = невалидна, исключается из `priceComparison` (ранг/дельта) и `minRawRub` (Мин.цена) через общий `IqotCurrencyConverter::firstPositivePrice($offer)` (первая положительная из price_per_unit→total_price→price, иначе null). Бейдж-счётчик «N ▾» (report_offers_count) пока считает ВСЕ офферы вкл. нулевые — расхождение с таблицей сравнения (там нулевой не показан); если надо — вычитать невалидные из report_offers_count. Бэкфилл cmp_*/report_min_price — через `iqot:update-fx-rates --force`.

## Запрет повторной отправки при свежем отчёте (коммит 0c639a3)
`enqueueCatalogItem` no-op, если `hasFreshReport()` (бережём баланс; отчёт сам обновляется поллингом, пока submission собирает). В карточке каталога при свежем отчёте кнопка повторной отправки убрана; в разделе «Повторить» только для failed / устаревшего completed. (Раньше «Обновить» в карточке повторно гнал на расценку — баг.)
