Крупная сессия (2026-08-04..06) по качеству авто-матчинга позиций заявки в каталог. Эталон истины — каталог в ОТПРАВЛЕННЫХ КП (`outbound_quote_items.matched_catalog_item_id`); «КП = истина всегда» (решение заказчика). Отработанные заявки НЕ правим — только тюним матчер.

**Инструмент:** `php artisan catalog:match-eval` — read-only регресс-харнес (txn+rollback, гарантия read-only). Флаги: `--nameonly` (только name-path, без артикульных подмен), `--control=N` (набор верных C-матчей, замер РЕГРЕССИЙ; фильтр payload method=C_name_vector), A/B-переключатели `--gate/--rawname/--nocat/--catgate`. Стр. аудита `/dashboard/catalog/match-audit` ([[reference_match_audit]]).

**Диагноз (тверд):** матчер ДЕТЕРМИНИРОВАН (seed подтвердил). Расхождения система≠КП: ~⅔ = артикульные ПОДМЕНЫ менеджера (не баг матчера, учить нельзя — стабильных алиасов лишь ~9-39), ⅓ = name-path (клиент дал только имя). На чистом name-path матчер слаб: correct ~7.5%, other_wrong ~32%. Из name-path ошибок 61% — категория ВЕРНА (виноват retrieval/rerank внутри), 39% — категоризация увела не туда.

**Принято на прод:** (1) raw-name retrieval — доп. trigram-проход по голому parsed_name (buildQueryText травит бренд+категория из KB; +7.5пт correct, без регресса; флаг `catalog.name_match.raw_name_retrieval`); (2) fixed LLM seed на rerank/validate (детерминизм); (3) фильтр match-audit на уровне ЗАЯВКИ (кейс 9728, [[reference_cited_quote_invoice_routing]] рядом). **Отклонено замером:** ambiguity-gate по blended score (режет хорошее), nocat (ломает контроль), category head-noun gate (слеп к синонимам «Инвертор↔ЧП»). Все — за флагами default off.

**Корень (в работе):** таксономия KB = 36 `equipment_categories` (общая для заявок identification_category_id И каталога equipment_category_id), у каталога ещё богатый `part_type` (231, ~6× мельче). Переоценка по 3322 КП-подтверждённым верным матчам (KB-кат→part_type, «чистота»): ~23 оставить, СЛИТЬ Плата управления+Контроллер+Частотный преобразователь, ДРОБИТЬ грабь-бэги (Привод дверей 38%, Ролик 43%, Поручень/Ступень эск., Тормоз гл.привода), ЧИНИТЬ мис-маппинг (КВШ→отводной блок, Порог→башмак, Светильник→трансформатор). Отчёт-артефакт: claude.ai/code/artifact/d8da8b87-5b18-4afe-8d4b-4f1d037e7f82.

**КЛЮЧЕВОЙ ВЫВОД симуляции (потолок таксономии):** прогон 97 name-path ошибок против part_type-гранулярности — **81% ошибок: верный и ошибочный каталог в ОДНОМ part_type** (ошибка не той МОДЕЛИ/РАЗМЕРА/ПАРАМЕТРА внутри типа: «Порог L=2064 vs 1530», «ОС V=1,0 vs 1,6 м/с», «Поручень C879 vs Sigma»). Лишь 19% разделяются таксономией, реалистично ~8%. Значит **переработка категорий (merge/split/fix) закрывает ≤8% ошибок** — worth для гигиены данных и путаницы Плата↔Контроллер, но НЕ главный рычаг. **Настоящий рычаг = различение по размеру/параметру/модели ВНУТРИ типа + увод в ручную, где клиент не дал отличающей детали** («этажная плата» без модели). Следующий шаг тюнинга — dimension/parameter extraction+matching, НЕ таксономия. ОТКРЫТО: резолвер категории (CategoryRefinementService) промахивается на грубом уровне («Шкив ОС»→«Безопасность»), но это второстепенно.
