**Грабля данных каталога:** позиция 1С нередко имеет ОДНОВРЕМЕННО `stock_available>0` И большой `lead_time_days` (`СрокПоставки`) — на проде **3457 позиций** с `stock>0 & lead≥8нед` (`СвободныйОстаток` = наличие сейчас, `СрокПоставки` = срок пополнения). Старый PDF-шаблон КП безусловно дописывал `≈ N нед` рядом со «Со склада» → бредовое «**Со склада ≈ 12 нед**» (кейс M-2026-5291 / M07746: stock=8, lead=84д).

**Правило срока (commit 02ca285, 2026-06-22)** — выводится из наличия vs запрошенного кол-ва, реализовано в **`QuotationItem::deliveryRows()`**:
- `stock ≥ qty` → «Со склада» (БЕЗ недель);
- `stock = 0` (или null-флаг !in_stock) → «Под заказ ≈ N нед» если `lead_time_days>0`, иначе **«Под заказ (срок уточняется)»** (НЕ голое «Под заказ» — в каталоге ~45% под-заказ позиций с lead=0/пусто; выдуманное число не ставим). Заказчик: для под-заказа срок указывать обязательно. Legacy/авто-`delivery_text` «Под заказ N нед» (ставится в fillSnapshotFromCatalog/Editor при !in_stock && lead) показывается verbatim как override;
- `0 < stock < qty` (частично) → **ДВЕ строки под ОДНИМ номером позиции** (rowspan только на № и НАЗВАНИИ; номер НЕ дробится на 4.1/4.2 — заказчик: раз имя одно, под-пункты не нужны): строка наличия qty=stock «Со склада» + строка остатка qty=(qty−stock) «Под заказ ≈ N нед». Дробятся **кол-во / срок / ЦЕНА / сумма** (цена одна, но повторяется на каждой строке — иначе у «Под заказ» сумма есть, а цена пустая, заказчик заметил); суммы/НДС делятся пропорционально (вторая добирает остаток после округления → итог по позиции = сумма строк). `delivery_text` (ручной) — абсолютный override, без разбивки.

**Снапшот количества:** новая колонка **`quotation_items.catalog_stock_available`** (раньше снапшотился только bool `catalog_in_stock`, которым частичное покрытие не выразить). Заполняется в обеих точках создания позиции — `QuotationService::fillSnapshotFromCatalog` (autoFill/refreshPrices) и `Editor::addItem`; миграция бэкфиллит из текущего `catalog_items.stock_available`. Legacy без снапшота (null) → фоллбэк по флагу `catalog_in_stock`, без противоречивых недель.

**Комментарии в КП (commit 495bdeb, 2026-06-22):** печатаются в итоговом PDF. (1) **Общий** — НОВОЕ поле `quotations.client_comment` (textarea «Комментарий к КП (печатается в PDF)» в Editor; блок «Комментарий» в PDF после итогов, перед «Условиями»). **Грабля:** НЕ путать с `quotations.notes` — туда `markCancelled/markRejected` дописывают «Отменено: …»/«Отклонено: …» (внутреннее, клиенту нельзя); поэтому отдельное поле. (2) **По позиции** — `quotation_items.notes` (поле было, но без инпута/печати, 0 использований; внутренне не пишется → безопасно): инпут «Комментарий: Аналог / Замена / сверить параметры…» в строке позиции редактора; в PDF — курсивом под названием (`.note`, акцентный цвет). Editor::updateQuotationField/updateItemField уже разрешают эти поля.

**Выбор получателя КП из организации (commit cea9eb3, 2026-06-22):** в редакторе КП (`Quotations\Editor`, блок «Заказчик») — подстановка получателя из ИЗВЕСТНОЙ организации, а не только руками. У клиента бывает несколько организаций (кейс M-2026-2009 / `<адрес>` → 3 орг.: Модтфил 20% / ЛИФТДОМ 0% / МОДТФИЛ-СЕРВИС 0%). `Editor::clientOrganizations` = `request.organization_id` + организации контакта по `client_email` (M:N); `searchedOrganizations` — поиск любой по name/ИНН. `applyOrganization($orgId)` заполняет `recipient_name/inn/address/card_text` (= org.requisites_text) + **`discount_percent` из `organization.discount_percent`** (назначенная скидка) → recalcTotals (с правилом MAX и реальной скидкой ниже). UI: quick-pick кнопки привязанных орг. (с бейджем скидки) + поиск, подсветка выбранной по ИНН/имени.

**Реальная скидка в КП (commit 829dc33, 2026-06-22):** финальная цена = `QuotationService::computeFinalUnitPrice` = **MAX(цена×(1−назначенная%), price_min)** (не продаём ниже минимальной продажной из MDB). Если минималка перебила назначенную скидку — фактическая скидка МЕНЬШЕ выбранной, и в КП показываем **РЕАЛЬНУЮ**, не назначенную. `QuotationItem::realDiscountPercent()` = `(1 − final_unit_price/catalog_unit_price)×100` (null если по факту скидки нет) — используется в бейдже «−N%» per-item. Итоговая «Скидка N%» = `discount_amount/subtotal×100` (а не `quotation.discount_percent`), чтобы % соответствовал ₽. Заказчик: «берём максимум из 2 цен (со скидкой / минимальная продажная); если выбрана минимальная — скидку пересчитать». Пример: catalog=1000, price_min=850, назначено 30% → final=850, реально 15%.

**PDF-рендер** (`resources/views/quotations/pdf-template.blade.php`, единственный рендер КП — и превью, и download через `QuotationPdfService::render`): цикл по `deliveryRows()` рисует 1–2 `<tr>`; имя+цена через **rowspan** (общие для под-строк), № показывает `position`+`.1/.2`, срок/кол-во/сумма — по под-строке. dompdf rowspan проверен на проде (pdftotext Q#36: «1.1 Со склада / 1.2 Под заказ»).
