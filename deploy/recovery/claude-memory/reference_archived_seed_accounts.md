Часть исторических заявок (импорт почтового бэклога) назначена на **архивные** аккаунты, которых НЕТ в выпадающем фильтре менеджеров (фильтр = `User::active()` = `whereNull('archived_at')`, см. [Pool.php](app/Livewire/Requests/Pool.php) `managerOptions` ~line 420):
- плейсхолдеры `man1/man2/<адрес>` (id 7/5/6, названы «Илья Курзаев»/«Менеджер 2»/«Менеджер 3»)
- тестовые seed `<адрес>`, `<адрес>` (id 1 «Менеджер Иванов», id 2 «РОП Сидоров»)

Все они `archived_at IS NOT NULL` (scope `active()` архивных режет; колонка `is_active` — NULL у всех, не используется в `active()`).

**Следствие (грабля):** в любом отчёте «по менеджерам» с общим счётчиком «Все» будет перекос — «Все» считает заявки всех владельцев (вкл. архивных), а сумма по выбираемым менеджерам покроет только активных. Кейс: бакет «Наш отказ» показывал 1911, а сумма по 7 менеджерам = 470 (разница 1441 = 1132 на seed + 309 дубль-Курзаев). Если увидишь такое расхождение — почти наверняка это архивные-владельцы, а не потерянные данные.

**Инвариант-фикс:** аналитические выборки «по менеджерам» ограничивать активными владельцами — `whereHas('assignedUser', fn($q)=>$q->active())` — тогда «Все» = сумме по менеджерам по построению. Применено в бакете `refused` ([[request-merge]] тут ни при чём — это про пул).

**2026-07-22:** пробовали слить дубль Курзаева id7(man1@)→id10, потом **ОТКАТИЛИ** по просьбе заказчика (эти 311 старых заявок не должны числиться за реальным Курзаевым). Итог — id7 и id10 в исходном состоянии (311 / 1555), Курзаев в бакете = 82. Разницу «Все vs менеджеры» закрывает НЕ слияние, а фильтр активных владельцев (`whereHas assignedUser active`) в бакете refused.

Грабля отката (durable): raw `DB::table()->update(assigned_user_id)` следа не оставляет, но **аудит `request_assignments`** позволяет точно восстановить набор — заявки, у которых ПОСЛЕДНЕЕ назначение (`distinct on(request_id) ... order by assigned_at desc,id desc`) = нужный user_id. Колонки: `request_id, user_id (=назначенный), by_user_id, reason, assigned_at`. Кросс-проверка датой (заявки созданы до появления аккаунта-получателя) подтвердила набор 311/311.
