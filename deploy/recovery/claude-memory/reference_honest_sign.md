Раздел **«Честный знак»** — `/dashboard/honest-sign`, пункт рейла ⧉, роли `head_of_sales/director/secretary/procurement/admin` (гейт на роуте + продублирован в left-rail; снабжение добавлено commit 3986938). Commit ae8ace5, 2026-07-20.

## ГЛАВНОЕ про формат исходных PDF (иначе всё сломается)
- **Одна страница = один DataMatrix** (один код маркировки). В примере M05143 — 5 кодов = 5 страниц.
- Код напечатан текстом под картинкой, но **РАЗОРВАН на два фрагмента** (префикс + хвост), между которыми визуально стоит подпись артикула. Это НЕ одно последовательное поле — проверено режимом `pdftotext -raw` (порядок отрисовки): префикс и хвост идут отдельными text-run'ами. «Просто извлечь текст» даёт мусор: `0104681008402919215f8 : M05143 !BGniPQV0JIljDs&R`. Части надо сшивать, подпись выкидывать. У 5-го кода хвост вообще отделён пустой строкой — наивный парсер «следующая строка» ломается.
- **Распознавать картинки НЕ нужно** — у штатных PDF поставщика есть текстовый слой. Декодер DataMatrix (libdmtx/zxing) сознательно вне скоупа: заказчик выбрал «сначала текст, декодер потом». Скан без текстового слоя → понятная ошибка, а не пустой результат.

## Структура страницы (Smalot `Page::getTextArray()`)
```
[1] 0104681008402919215f8   ← префикс кода
[2] !BGniPQV0JIljDs&R       ← хвост кода
[3..n] слова наименования (с переносами: «ДОПОЛНИТЕЛЬ» «НЫХ»)
[n+1] «Артикул: M05143»     ← MZ-ID, связка со строкой Excel
```
Парсер `App\Services\HonestSign\HonestSignPdfParser` идёт ПОСТРАНИЧНО по фрагментам (не по сплошному тексту документа), `smalot/pdfparser` уже в проекте — внешний `pdftotext` не нужен.

## Формат кода и ячейки КИЗ
- Код (GS1 + ЧЗ), **38 символов**: `01` + GTIN(14) + `21` + серийник и крипто-хвост(20). GTIN = `substr($code,2,14)`.
- Ячейка **КИЗ**: коды через `;` + перенос строки, **у последнего разделителя НЕТ**, `wrapText=true`. Формат сверен с ручной заливкой заказчика побайтово (`formatKizCell()`).

## Заполнение файла поставки — `HonestSignExcelFiller`
- Шапка ищется **по заголовкам** «MZ-ID» / «GTIN» / «КИЗ», а НЕ по буквам колонок: в эталоне заказчика она на **5-й строке** (столбцы C/E/F), жёсткие буквы сломаются на другом файле. Скан шапки — первые 30 строк.
- Строка товара — по **MZ-ID = артикул из PDF** (нормализация: upper + без пробелов).
- Пишем **только 2 ячейки** (GTIN, КИЗ) — веса, цены, формулы, итоги не трогаем, файл возвращается тем же .xlsx.
- **GTIN пишем строкой** (`setCellValueExplicit` TYPE_STRING): в числовом формате ведущий ноль `04681…` теряется.
- Артикулы, которых нет в файле → в `unmatched`, коды всё равно показываются для ручного копирования.

## Журнал
`honest_sign_batches` (загрузка: кто/когда/сводка/warnings) + `honest_sign_codes` (код построчно: code/gtin/serial/article/product_name/source_file/page). Поиск «в какую поставку ушёл этот КИЗ» + детект **повторной подачи** (предупреждение при разборе). **Сами PDF/xlsx НЕ храним** — только распознанные коды (см. [[email-storage-pruning]], квота БД). Заполненный файл лежит в `storage/app/honest-sign/` и удаляется при скачивании (`deleteFileAfterSend`).

## Инструмент «Названия по каталогу» (вкладка `names`, commit 418af42, 2026-08-13)
Отдельная задача, НЕ про DataMatrix: xlsx со столбцом MZ-ID → на выходе тот же файл + доп. колонка «Наименование (из каталога)» СРАЗУ СПРАВА от артикула (русское `catalog_items.name` по `sku`). `HonestSignCatalogNameFiller::fill`: опознание столбца артикула по заголовку (переиспользует рецепт `HonestSignExcelFiller` — H_ARTICLE `mz-id/mzid/…` ИЛИ «…торг-12» с артикулом до первой запятой), читает ВСЕ артикулы ДО `insertNewColumnBefore` (иначе буквы столбцов, включая torg12, сдвигаются и прочитается не то), один batch-запрос `whereIn('sku')` + orderByDesc active, `setCellValueExplicit` TYPE_STRING. Отчёт matched/total/unmatched. Файл в `storage/app/honest-sign/`, удаляется при скачивании. НЕ пишет в журнал (это не разбор кодов). Проверено на образце 8.12-Z.xlsx: 149/149 сматчено, колонка E(MZ-ID)→новая F→старая Specification в G; артикул с ведущим `\t` подхватился (normalizeArticle чистит пробелы). Вкладки компонента теперь parse|names|journal. Роут/рейл НЕ менялись — деплой без route:cache (только view:clear).
